### [Genome language models generate viable bacteriophage genomes](https://www.reddit.com/r/MachineLearning/comments/1vjj4pr/r_generative_design_of_novel_bacteriophages_with/) ⭐️ 9.0/10

Researchers report the first generative design of viable bacteriophage genomes using frontier genome language models Evo 1 and Evo 2. Using the lytic phage ΦX174 as a design template, they generated whole-genome sequences with realistic genetic architectures and desirable host tropism. Experimental testing of the AI-generated genomes yielded 16 viable phages with substantial evolutionary novelty. This demonstrates an untested capability of genome language models to produce functional sequences at the scale of whole genomes, with implications for AI-driven synthetic biology.

reddit · r/MachineLearning · /u/moschles · Aug 9, 07:11

**「Background」** Evo 1 and Evo 2 are open-source foundation models that process and generate genomic sequences at single-nucleotide resolution, trained directly on raw DNA rather than on natural language. Evo 1 was developed by researchers at the Arc Institute and the University of California and released in 2024, while Evo 2, published in Nature in March 2026, is a 40-billion-parameter model with a 1-megabase context length trained on over 9 trillion nucleotides. These genome language models have mainly been used for zero-shot prediction tasks such as scoring gene essentiality, and the ability to generate functional whole genomes had remained untested.

**「Impact」** Because the generated phages can be tested as a cocktail that rapidly overcomes ΦX174-resistance in three E. coli strains, this work provides a concrete foundation for designing phage therapies against rapidly evolving bacterial pathogens. However, experts caution that the models do not yet produce viable genomes out-of-the-box and do not explain why some genomes are viable, so experimental screening and validation remain necessary.

### [GitHub Models Retired, Disrupting Actions-Based LLM Workflows](https://simonwillison.net/2026/Aug/9/github-models-is-now-retired/#atom-everything) ⭐️ 7.0/10

GitHub Models was officially retired on July 30, 2026, according to a GitHub changelog, and Simon Willison only noticed on August 9 when his GitHub Actions workflow failed with the now-stale message that the service was temporarily unavailable during a scheduled retirement brownout. The service had offered a model playground and a unified API across multiple LLM providers, with the key benefit that code running in GitHub Actions could use the already-present GitHub API key to execute prompts, making it easy to build Continuous AI-style automation. GitHub did not disclose the reason for the shutdown, though Willison speculates that coding agent patterns made it prohibitively expensive to offer free or subsidized tokens. He updated his own repository workflow, swapping GitHub Models for an OpenAI API key with a monthly spending limit and now generating folder summaries using GPT-5.6 Luna.

rss · Simon Willison · Aug 9, 22:48

**「Background」** GitHub Models was GitHub&\#x27;s unified LLM API and playground that let developers run prompts against multiple model providers, with the notable advantage that GitHub Actions workflows could use the repository&\#x27;s existing GitHub API key without extra setup. GitHub first announced the retirement in June 2026, stopped onboarding new customers on June 16, and fully retired the service on July 30, 2026, removing the playground, model catalog, inference API, and bring-your-own-key \(BYOK\) support. The shutdown left CI workflows that relied on GitHub Models&\#x27; built-in key handling without a drop-in replacement, forcing developers to migrate to alternative API providers or configure their own credentials.

**「Impact」** Developers who relied on GitHub Models&\#x27; unified LLM API inside GitHub Actions now lose that no-extra-key workflow and must migrate to paid providers, as Simon Willison did by switching to an OpenAI API key with a monthly spending limit. The retirement also forces teams to audit and replace provider-specific assumptions in their CI pipelines, a practical exit-planning step for any managed AI platform dependency.

Elon Musk announced during SpaceX&\#x27;s first public earnings call a plan to build an automated factory on the Moon. SpaceX reported $7.8 billion in quarterly revenue and a $205 million loss in its space division due to Starship investment. telegram · zaihuapd · Aug 9, 05:37

**「Background」** The Moon has no atmosphere and experiences extreme temperature swings, with about 14 days of sunlight followed by 14 days of darkness at any given location, making lunar operations challenging. SpaceX&\#x27;s Starship is a reusable heavy-lift rocket currently under development, intended to carry large payloads to the Moon, Mars, and beyond.

**「Impact」** If realized, this plan could dramatically reduce satellite launch costs by manufacturing them in-situ on the Moon and eliminating the need to lift them from Earth&\#x27;s gravity well.

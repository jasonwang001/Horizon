### [OpenAI Jalapeño chip outperforms Nvidia GB300 in inference](https://newsletter.semianalysis.com/p/openai-jalapeno-better-than-nvidia) ⭐️ 8.0/10

OpenAI&\#x27;s first custom inference ASIC, Jalapeño, reportedly outperformed Nvidia&\#x27;s GB300 in benchmark tests, with SemiAnalysis analyzing its total cost of ownership and throughput per megawatt. On GPT-OSS 120B, DeepSeek R1 670B, and Kimi K2.5 1T, the chip produced 1.5–1.9x more work per watt at peak throughput, cut end-to-end latency by 1.7–3.6x, and delivered 2.1–4.1x higher performance in high-interaction scenarios. Jalapeño is rated at 700W but sustained no more than 550W in testing, and was developed with Broadcom; it is not used for training and was not compared with Nvidia&\#x27;s newly shipping Vera Rubin. OpenAI plans to deploy the chip in its own compute facilities before the end of the year, while a second generation is in deep development and a third is being designed.

hackernews · Semianalysis · Aug 25, 14:06 · [Discussion](https://news.ycombinator.com/item?id=49434378)

**「Background」** Nvidia&\#x27;s GB300 represents a leading Blackwell-based inference system, while OpenAI previously depended on external GPU suppliers and has been diversifying into custom silicon. ASICs like Jalapeño are tailored to specific workloads such as transformer inference rather than general-purpose training, and benchmarks against open models like DeepSeek and Kimi have become a common reference point in the AI hardware race.

**「Impact」** Because the chip is earmarked for OpenAI&\#x27;s own datacenters and is not for training or immediate commercial sale, the near-term impact is mainly on OpenAI&\#x27;s internal inference costs and on the competitive pressure it places on Nvidia&\#x27;s accelerator roadmap.

**「Community discussion」** Commenters largely saw the benchmark results as evidence that the inference-chip market is entering an early competitive phase, drawing comparisons to the 3dfx/Riva/PowerVR era and questioning whether it will make AI hardware affordable. Others noted the use of DeepSeek and Kimi as reference models, speculated about baking model weights directly into chips for older models, and observed that human speech remains about 22x more efficient than these chips on a token-per-joule basis.

Nitter allows users to view tweets without ads, tracking, or JavaScript, and was widely used by privacy-conscious users and those avoiding X&\#x27;s restrictions. On 24 August 2026, X Corp sent cease-and-desist letters to Nitter&\#x27;s developer, demanding that instances and the GitHub repository be taken down over alleged scraping, leading to instances such as nitter.net going offline and work halting while legal advice is sought.

**「Impact」** Users and organizations that depended on public Nitter instances to read X/Twitter content without an account or tracking, including local councils that use X for announcements, will lose that access at least temporarily. ### [EVE Online Begins Python 3 Migration of 2.4M-Line Codebase](https://simonwillison.net/2026/Aug/25/eve-online-move-to-python-3/) ⭐️ 7.0/10

EVE Online has officially begun migrating its 2.4-million-line codebase from Stackless Python 2.7 to Python 3, using the futurize conversion script followed by manual review of roughly 20,000 places where Python 2 and Python 3 behavior differs, such as integer division \(1 / 2 becoming 0.5 instead of 0\). The migration is a major step for a game that has run on Stackless Python since its 2003 launch, with the last major upgrade being Stackless Python 2.7 in 2010. The announcement does not explain how Stackless will be replaced, though EVE Online&\#x27;s developer CCP presented a solution last year in &\#x27;Scheduling in Carbon: Leaving Stackless Python Behind,&\#x27; describing the open-source carbonengine/scheduler library used for EVE Frontier. This matters as one of the largest and longest-running Python production codebases finally moves to the modern language version.

rss · Simon Willison · Aug 25, 22:59

**「Background」** Stackless Python is a variant of CPython that adds microthreads and tasklets, allowing massively concurrent game server logic without the overhead of OS threads. EVE Online&\#x27;s server-side simulation has relied on this model for over two decades, and moving to standard Python 3 means the team must also solve the concurrency and scheduling problems that Stackless previously handled.

**「Impact」** For EVE Online&\#x27;s developers, the migration requires auditing roughly 20,000 Python 2/3 behavioral differences across 2.4 million lines and choosing a replacement for Stackless-style scheduling, with no player-facing changes announced.

### [Hybrid Search with PostgreSQL, pgvector, and Qwen3 Embeddings](https://www.reddit.com/r/MachineLearning/comments/1vxyrsr/how_we_built_a_sota_search_engine_using/) ⭐️ 7.0/10

The Qwen3 Embedding series provides text embedding and reranking models in sizes from 0.6B to 8B, allowing efficient deployment for production retrieval systems.

**「Impact」** Engineers building hybrid search on PostgreSQL can use this production setup as a concrete reference, combining pgvector-based semantic search with keyword matching and separating batch from live embedding serving on Hugging Face infrastructure.
